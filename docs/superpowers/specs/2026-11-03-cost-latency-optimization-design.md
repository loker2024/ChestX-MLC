# `cost.py` 端到端耗时优化设计

## 背景与目标

当前 `src/cost.py` 已按 study 作为最小计时单元，支持多模型融合、视角加权、预热、逐轮 CSV 写出和 submission 一致性校验。V100 实测四模型组合约为 96.7 / 100.5 ms，已接近 100 ms 上限。优化目标是降低真实端到端推理耗时，并让四模型组合在相同硬件与样本分布下留出稳定余量。

本次优化保持以下契约不变：

- study 级计时、3 轮汇总、预热不计入成绩、100 ms 判定；
- 读取图片、解码、预处理、前向、study 聚合、融合、逐图写出与 `flush()` 的计时边界；
- 单模型和多模型 `probability` / `logit` 融合公式；
- `fp32` / `fp16`、设备同步、视角加权和 submission 概率一致性；
- 现有 CLI 参数、报告字段和退出码语义。

## 方案

### 1. study 内一次解码

在 `src/infer/predict.py` 增加面向 study 的内部推理路径：先将该 study 的图片路径解码成内存中的图像对象，再交给各模型的预处理阶段。每张图片在一个 study 内只读取和解码一次。缓存生命周期限于当前 study，study 完成后释放引用，不跨 study 持有像素数据。

### 2. 按预处理签名共享批次

为每个模型计算包含输入尺寸、颜色通道、归一化参数和其它影响输出的预处理字段的不可变 `transform_key`。按 key 将模型分组：

- 同 key 的模型共享一批预处理后的张量，并分别执行前向；
- 不同 key 的模型只共享已解码图像，各自执行必要的 resize/normalize；
- key 缺失、无法比较或配置不完整时自动回退为各模型独立预处理，不能静默复用不兼容张量。

预处理后的张量在当前 study 内保持只读语义，模型前向不得原地修改共享数据。输出概率仍通过现有聚合和融合函数计算。

### 3. 保守的前向调度

继续逐模型前向，不引入 CUDA stream 并行。原因是当前主要瓶颈位于 CPU 解码/预处理；stream 并行会增加显存占用、同步复杂度和尾延迟风险。该设计先消除确定的重复工作，再根据实测结果决定是否需要后续单独评估前向并行。

### 4. 写出路径收紧

保留每个 study 写完后 `flush()` 的规则边界，但减少循环内临时对象构造：预先缓存列顺序、字符串化的 study/subject/image 标识和概率格式化所需的固定结构，避免改变 CSV 字段或浮点文本精度。轮级打开和关闭仍在计时范围内。

## 模块边界

- `src/infer/predict.py`：负责解码一次、预处理分组、张量复用和模型前向；不负责计时判定或报告格式。
- `src/cost.py`：负责参数解析、study 计时编排、文件写出、设备同步、汇总和退出码；不复制 transform 实现。
- `src/infer/profiling.py`：保持 `StudyJob`、计时统计、submission 比对和报告数据结构不变，仅在需要时补充新路径的统计字段。

## 错误处理

- 任一图片解码、预处理或前向失败，整次运行返回现有参数/模型错误码 2，不输出部分成功结论。
- 共享批次的 shape、dtype 或 device 与模型要求不匹配时，回退到独立预处理；若独立路径也失败，则按错误码 2 处理。
- 共享路径计算出的概率若不满足有限值与 `[0, 1]` 范围校验，按现有预测错误处理，不继续写出或比较。
- 多模型融合与 submission 的最大绝对差仍由 `--tolerance` 判定；优化不能通过放宽容差掩盖数值变化。

## 测试计划

1. 为预处理分组增加单元测试：同一 `transform_key` 只执行一次批次预处理；不同 key 各执行一次；多图 study 的 batch 维度、dtype 和 device 正确。
2. 在 `tests/test_cost.py` 增加单模型、同尺寸双模型、不同尺寸双模型和视角加权模型的回归用例，验证优化前后概率差不超过既有 tolerance，逐图输出行数和字段完全一致。
3. 运行 focused 测试：`python -m pytest tests/test_cost.py tests/test_dataset.py`。
4. 运行全量测试：`python -m pytest`，并执行 `git diff --check`。
5. 在可用 V100/T4 环境用同一 100-study / 5-study 样本复测，记录 mean、median、p95、max、round overhead、最大概率差和退出码；本机 CPU 结果只作为结构验证，不替代目标 GPU 结果。

## 成功标准

- 既有 focused 与全量测试通过；
- 单模型、多模型、视角加权和不同输入尺寸的 submission 一致性均通过；
- 在相同 GPU、样本目录、模型权重和参数下，四模型平均 study 延迟相对当前基线下降，并在重复运行中稳定低于 100 ms；
- 报告字段和退出码保持向后兼容。

## 范围外事项

本次不修改训练配置、模型结构、融合权重、submission 文件、赛题阈值口径或官方 100 ms 规则；不引入外部数据或新的 CUDA 依赖。
